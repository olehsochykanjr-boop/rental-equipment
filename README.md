# Прокат обладнання

Клієнт-серверний вебзастосунок для обліку прокату техніки в навчальному закладі: студенти подають заявки на ноутбуки, камери, датчики та інше обладнання, а адміністратор (комірник) підтверджує видачу й приймає повернення.

Навчальний проєкт з дисципліни «Розробка клієнт-серверних застосунків».

## Можливості

**Гість** (без входу)
- переглядає каталог техніки з фільтрами за категорією та статусом

**Студент**
- реєструється та входить
- подає заявку на вільну техніку з датою повернення
- бачить свої заявки, їхні статуси та причину відхилення
- змінює або скасовує свою заявку, поки її не розглянули

**Адміністратор**
- бачить усі заявки з фільтром за статусом
- підтверджує або відхиляє заявку (з причиною)
- фіксує повернення техніки
- додає, змінює техніку, ставить її «у ремонт»
- переглядає історію видач по кожній одиниці техніки
- переглядає статистику (за видом техніки, місяцем, студентом, прострочені повернення)

## Встановлення

### Що потрібно
- [Node.js](https://nodejs.org/) версії 18 або новіше (перевірка: `node -v`)
- [Git](https://git-scm.com/)

### Кроки

```bash
# 1. Клонувати репозиторій
git clone https://github.com/olehsochykanjr-boop/rental-equipment.git
cd rental-equipment

# 2. Встановити залежності
npm install

# 3. Створити файл налаштувань
#    Windows (cmd / PowerShell):
copy .env.example .env
#    macOS / Linux:
# cp .env.example .env

# 4. Створити базу даних і наповнити її тестовими даними
npm run db:init

# 5. Запустити сервер
npm start
```

Відкрий у браузері: **http://localhost:3000**

### Налаштування (.env)

Файл `.env` не потрапляє в репозиторій, бо містить секрет. Зразок лежить у `.env.example`:

| Змінна | Призначення |
|---|---|
| `PORT` | порт сервера (за замовчуванням 3000) |
| `JWT_SECRET` | секретний ключ для підпису токенів. Задай довгий випадковий рядок |

### Скидання бази

Команда `npm run db:init` видаляє стару базу й створює нову із тестовими даними. Її можна запускати скільки завгодно разів.

## Як користуватись

1. Відкрий http://localhost:3000. Без входу видно лише каталог.
2. **Студент:** натисни «Увійти» (або зареєструйся). На вільних картках з'явиться кнопка «Подати заявку». Статус заявок дивись у вкладці «Мої заявки», там можна змінити чи скасувати заявку, поки вона «Очікує».
3. **Адміністратор:** увійди як `oleh@example.com`. У вкладці «Усі заявки» натискай «Підтвердити» або «Відхилити», а коли студент повертає техніку, «Прийняти повернення». На картках каталогу є кнопки «Змінити», «Історія» та «У ремонт». Вкладка «Статистика» показує зведення.

### Життєвий цикл заявки

```
pending (очікує) ──► approved (підтверджено) ──► returned (повернено)
        ├──────────► rejected (відхилено адміном, з причиною)
        └──────────► cancelled (скасовано студентом)
```

Підтвердження заявки автоматично робить техніку `rented`, повернення знову `available`.

### Правила предметної області

- Одну одиницю техніки не можна видати двом студентам одночасно.
- Заявку можна подати лише на техніку зі статусом `available`.
- Дата повернення не може бути в минулому.
- Студент бачить, змінює й скасовує лише свої заявки, і лише поки вони `pending`.
- Підтверджувати, відхиляти, приймати повернення та керувати довідником може лише адміністратор.
- Статус `rented` змінюється тільки через заявки, вручну його виставити не можна.
- Пароль зберігається лише у вигляді хешу.
- При реєстрації роль завжди `student`, адміністраторів створює лише скрипт ініціалізації бази.

## REST API

Усі дані передаються у форматі JSON. Захищені маршрути вимагають заголовок:

```
Authorization: Bearer <токен>
```

Токен повертає `POST /api/auth/login`.

### Авторизація

| Метод | Маршрут | Доступ | Призначення |
|---|---|---|---|
| POST | `/api/auth/register` | усі | Створити студента |
| POST | `/api/auth/login` | усі | Увійти, отримати токен |

### Техніка

| Метод | Маршрут | Доступ | Призначення |
|---|---|---|---|
| GET | `/api/equipment?category=&status=` | усі | Список із фільтрами |
| GET | `/api/equipment/:id` | усі | Одна одиниця |
| POST | `/api/equipment` | адмін | Додати техніку |
| PUT | `/api/equipment/:id` | адмін | Змінити техніку або статус (`available` / `maintenance`) |
| GET | `/api/equipment/:id/history` | адмін | Історія видач |

### Заявки

| Метод | Маршрут | Доступ | Призначення |
|---|---|---|---|
| POST | `/api/rentals` | авторизований | Подати заявку |
| GET | `/api/rentals?status=` | авторизований | Студент бачить свої, адмін усі |
| GET | `/api/rentals/:id` | власник або адмін | Одна заявка |
| PUT | `/api/rentals/:id` | власник | Змінити дату чи примітку (лише `pending`) |
| DELETE | `/api/rentals/:id` | власник | Скасувати заявку (лише `pending`) |
| PATCH | `/api/rentals/:id/approve` | адмін | Підтвердити |
| PATCH | `/api/rentals/:id/reject` | адмін | Відхилити (`{ "reason": "..." }`) |
| PATCH | `/api/rentals/:id/return` | адмін | Зафіксувати повернення |

### Статистика

| Метод | Маршрут | Доступ | Призначення |
|---|---|---|---|
| GET | `/api/stats` | адмін | Зведення |

### Приклад: подати заявку

Запит:

```http
POST /api/rentals
Content-Type: application/json
Authorization: Bearer <токен>

{
  "equipmentId": 1,
  "dueDate": "2026-10-20",
  "notes": "для лабораторної"
}
```

Успішна відповідь `201 Created`:

```json
{
  "id": 21,
  "userId": 2,
  "equipmentId": 1,
  "requestedAt": "2026-10-11",
  "dueDate": "2026-10-20",
  "returnedAt": null,
  "status": "pending",
  "rejectionReason": null,
  "notes": "для лабораторної"
}
```

Помилка `400 Bad Request` (техніка зайнята):

```json
{ "error": "Ця техніка зараз недоступна" }
```

### Коди відповідей

| Код | Значення |
|---|---|
| 200 / 201 | успіх / створено |
| 400 | некоректні дані або порушено правило (наприклад, техніка зайнята) |
| 401 | немає токена або він недійсний |
| 403 | немає прав (не адмін, чужа заявка) |
| 404 | запис не знайдено |

Готові приклади всіх запитів лежать у файлі [`tests/api.http`](tests/api.http). Для запуску потрібне розширення VS Code **REST Client**.

## База даних

Три таблиці: `users`, `equipment`, `rentals`. Схема лежить у [`server/db/schema.sql`](server/db/schema.sql) і використовує `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE` та `CHECK`.

```
users 1 ──── N rentals N ──── 1 equipment
```

Статистика не зберігається, а обчислюється запитами.

## Безпека

- Паролі хешуються через bcrypt, у базі лише хеш.
- Авторизація через JWT, термін дії токена 7 днів.
- Права перевіряються на сервері (`authenticate`, `requireAdmin`, перевірка власника), а не лише в інтерфейсі.
- Ідентифікатор користувача береться з токена, а не з тіла запиту.
- Дані в інтерфейсі виводяться через `textContent`, що захищає від XSS.
- Секрети зберігаються в `.env`, який виключено з git.
